    Add a diagnostic capability to audio_async that exposes the current state of the audio capture system.

    The diagnostic output should make the internal state of the class observable while audio is being captured, allowing us to see how the circular buffer changes over time.

    At minimum, the diagnostics should expose the current running state, sample rate, buffer capacity, amount of valid captured audio, and current write position. These are the key values already identified for understanding the state machine and circular buffer.

    Understand that audio_async is a stateful object whose behavior depends on both its configuration and its continuously changing runtime state.

    The implementation should make it possible to answer:

    What changes when recording begins?

    What changes as samples arrive?

    Why does m_audio_len increase?

    Why does it eventually stop increasing?

    Why does m_audio_pos eventually wrap around?

    What does clear() actually reset?
